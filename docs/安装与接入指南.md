# DSH API Tools 安装与接入指南

本文适用于本插件仓库。目标是让 DSH Web 出现“API 工具”配置页，并仅让指定 Agent preset 拥有选定的 API 工具。安装命令会修改 DSH profile；执行前核对目标实例、备份现有 profile，不能用示例地址或密钥直接上线。

## 1. 结构与归属

| 文件或目录 | 作用 | 归属 |
| --- | --- | --- |
| `src/index.ts`、`cordis.patch.yml` | Web 宿主行；供 DSH 发现浏览器模块，不注册 Agent 工具 | 本插件 Git 仓库 |
| `src/tool.ts` | 按配置注册一条 API 对应一个 Agent 工具 | 本插件 Git 仓库 |
| `src/client/`、`lib/client.js` | DSH 右侧栏配置界面及构建产物 | 本插件 Git 仓库；`lib/` 不入 Git |
| `workspace/dsh-api-tools/` | 审查、输入输出及临时验证材料 | 上级 workspace，不入插件 Git |
| `$DSH_HOME/profiles/web/` | DSH Web profile 的包和补丁 | DSH 运行环境，非插件源码 |
| `$DSH_HOME/.agent-presets/<自定义名称>/` | 指定 Agent 的工具组合 | DSH 运行环境，非插件源码 |

本插件应使用独立 Git 仓库。不要把 DSH profile 或其他插件工程加入本仓库。

## 2. 安装前检查

1. 确认运行 DSH 的机器、`DSH_HOME`、Web profile 和 Node 版本。构建要求 Node `^22.18.0` 或 `>=24.11.0`。以实际运行实例为准。
2. 在 PowerShell 中查看目标 profile：

   ```powershell
   $env:DSH_HOME = '<DSH 用户目录的绝对路径>'
   Get-Content -LiteralPath "$env:DSH_HOME\profiles\web\package.json"
   Get-Content -LiteralPath "$env:DSH_HOME\profiles\web\cordis.patch.yml"
   ```

3. 核对已有依赖能否解析，尤其检查 `link:` 指向的本地目录是否存在。若 profile 原有插件已经失效，先修复原有依赖，再安装本插件，避免混淆故障来源。
4. 备份上述两个 profile 文件和计划修改的自定义 preset 文件。只追加本插件内容，不覆盖已有插件配置。确认 `dsh-better-sidebar` 已安装且在 Web bundle 列表中。
5. 核实要暴露的每条 API 的用途、HTTP 方法、参数、响应、权限和数据级别。写接口（POST、PUT、PATCH、DELETE）须确认目标 DSH 的审批策略。首轮建议只用只读 GET 接口验收。

## 3. 构建插件

在独立插件目录执行：

```powershell
Set-Location '<dsh-api-tools 仓库的绝对路径>'
git rev-parse --show-toplevel # 应为当前插件目录
npm ci
npm run typecheck
npm run build
Test-Path .\lib\index.js
Test-Path .\lib\tool.js
Test-Path .\lib\client.js
```

三个 `Test-Path` 都必须为 `True`。若系统默认 Node 不满足要求，先切换到符合 `package.json` 的 Node 再构建。`lib/` 被插件 Git 忽略，**本地 `file:` 安装前必须先构建**；将来若从 Git URL 或发布包安装，应在交付包内包含构建产物并验证 `files` 清单，不能假定 Git 仓库会携带 `lib/`。

## 4. 安装到 Web profile

使用目标 DSH 实例的 `dsh` CLI；若该命令不在 PATH，应先定位实际安装的 CLI，不要随便改用另一个源码树的 `pnpm dsh`。执行：

```powershell
dsh plugin --profile web add file:<dsh-api-tools 仓库的绝对路径>
dsh --profile web --dump-config
```

检查 `$DSH_HOME/profiles/web/package.json`：`dependencies` 中有 `dsh-api-tools`，`dsh.profile.bundles` 中也有 `dsh-api-tools`。`--dump-config` 输出应有 `api-tools-host` 行。该行只加载浏览器模块；此时 Agent 工具还不应出现。**不要**把 `dsh-api-tools/tool` 插入 Web profile 的宿主 `cordis.patch.yml`。

然后启动 Web profile 并检查右侧栏“API 工具”页：

```powershell
dsh --profile web
```

本插件界面可以保存浏览器草稿、导出 `dsh-api-tools.config.json`。草稿在当前浏览器的 localStorage；导出并不自动修改 DSH 配置，也不热更新工具。界面中的 Token 字段只填**环境变量名**，不能填密钥值。

## 5. 配置目标 Agent preset

从目标实例的 `standard` preset **复制**一份自定义 preset 到 `$DSH_HOME/.agent-presets/<自定义名称>/`，保留其原有行及 `preset.yml`，不要修改随 DSH 发布的 `standard` 文件。若已有专用自定义 preset，可在那一份上追加。仅在新 preset 的 `agent.cordis.yml` 中加入：

```yaml
- id: tool-api-collection
  name: dsh-api-tools/tool
  config:
    baseUrl: https://api.example.com
    tokenEnv: DSH_API_ORDER_TOKEN
    timeoutMs: 15000
    maxResponseChars: 20000
    endpoints:
      - name: get_order
        description: 根据订单号查询订单，仅返回已授权字段
        method: GET
        path: /orders
```

将示例值替换为已审核的真实 API。`baseUrl` 只能是 HTTP(S) 的协议、域名及可选端口，不含路径、凭据、查询或片段；`path` 以单个 `/` 开头，不含查询或片段。工具名以字母开头，后续仅字母、数字、下划线或连字符，最多 64 字符，并须在该 Agent 可见的其他工具中唯一。`description` 应告诉 Agent 何时调用、参数含义和结果含义，不写密钥或敏感样例。接口路径与方法由管理员固定，Agent 只能提供 `query`、`body` 两个 JSON 字符串参数；`GET` 不接受 body。

`tokenEnv` 可省略；若填写，必须以 `DSH_API_` 开头且只含大写字母、数字、下划线。将真实 Token 只注入 DSH 服务器进程的同名环境变量，不能放进 YAML、JSON、浏览器草稿、Git 或日志。当前插件只支持 Bearer Token；其他鉴权方式需要先开发适配。对多个不同服务地址应分不同插件实例或扩展配置模型，不能让 Agent 自由选择 URL。

浏览器导出的 JSON 与上面的 `config` 内容对应，需人工审核后转入 preset YAML。当前没有“上传 JSON 后自动启用”的服务器接口。修改 preset 后按目标 DSH 的 reload 机制或重启实例，并用新会话选择该自定义 preset；已有会话不会自动切换工具组合。

## 6. 验收标准

1. `dsh --profile web --dump-config` 能看到 `api-tools-host`，Web 页面出现“API 工具”；页面无插件加载错误。
2. 原有普通 Agent preset 不出现本批 API 工具；自定义 preset 的新会话只出现其配置的 API 工具。
3. 用一条已授权的只读 API 调用验收：核对请求路径、查询参数、HTTP 状态、`body` 和 `truncated`。4xx/5xx 会作为工具错误返回，错误消息最多携带 500 个响应字符；目标 API 的错误正文也不得包含密钥或其他敏感信息。
4. 用无效参数、未设置 Token、超时和超出响应上限的场景核对错误或截断行为；检查服务器日志和会话记录没有密钥值。
5. 对写接口单独核对 DSH 的审批提示、拒绝路径及目标服务审计记录。未通过审批验收前不要给 Agent 暴露写接口。

这些是验收步骤，**不是当前已通过的运行结果**。当前尚无真实 API 清单、Token、目标自定义 preset，也未在实际 DSH Web 实例执行安装和调用。

## 7. 回退

若只有工具调用异常，先在自定义 preset 中移除 `tool-api-collection` 行并让新会话使用更新后的 preset；保留原有 preset 其他行。若 Web 界面也需移除，在核对目标 profile 后执行：

```powershell
dsh plugin --profile web remove dsh-api-tools
dsh --profile web --dump-config
```

核对 `api-tools-host` 已消失，再重启或重载 Web 实例。必要时从安装前备份恢复 profile 文件；不要覆盖期间其他人新增的配置。插件源码仓库、上级 workspace 和其他插件 Git 仓库不因回退而删除。
