# DSH API Tools 安装与接入指南

本文适用于本插件仓库。目标是让 DSH 桌面版的“插件”页显示本组合包的 API 配置区，并仅让指定 Agent preset 拥有选定的 API 工具。安装会修改 DSH 桌面版 profile；执行前核对目标实例、备份现有 profile，不能用示例地址或密钥直接上线。

## 桌面版安装入口

在桌面版左侧打开“插件”，点击“添加插件”，填入本插件仓库的**本地绝对路径**，按预览确认包名为 `dsh-api-tools` 且它声明了组合包，再安装。安装成功后在“已安装”中打开该组合包详情并启用；配置区显示在组合包详情中。安装前须已执行 `npm run build`，确认 `lib/index.js`、`lib/tool.js`、`lib/client.js` 存在。桌面版 profile 是 `$DSH_HOME/profiles/desktop`。

配置区保存的是本机草稿，导出 JSON 后仍须审核并装载进指定 Agent preset；安装组合包本身不会把全部 API 自动赋给 Agent。

## 1. 结构与归属

| 文件或目录 | 作用 | 归属 |
| --- | --- | --- |
| `src/index.ts`、`src/preset.ts`、`cordis.patch.yml` | 桌面版宿主行和独立 preset 创建服务；不直接注册 Agent 工具 | 本插件 Git 仓库 |
| `src/tool.ts` | 按配置注册一条 API 对应一个 Agent 工具 | 本插件 Git 仓库 |
| `src/client/`、`lib/client.js` | DSH 插件详情配置界面及构建产物 | 本插件 Git 仓库；`lib/` 不入 Git |
| `workspace/dsh-api-tools/` | 审查、输入输出及临时验证材料 | 上级 workspace，不入插件 Git |
| `$DSH_HOME/profiles/desktop/` | DSH 桌面版 profile 的包和补丁 | DSH 运行环境，非插件源码 |
| `$DSH_HOME/.agent-presets/<自定义名称>/` | 指定 Agent 的工具组合 | DSH 运行环境，非插件源码 |

本插件应使用独立 Git 仓库。不要把 DSH profile 或其他插件工程加入本仓库。

## 2. 安装前检查

1. 确认运行 DSH 的机器、`DSH_HOME`、desktop profile 和 Node 版本。构建要求 Node `^22.18.0` 或 `>=24.11.0`。以实际运行实例为准。
2. 在 PowerShell 中检查目标 desktop profile。先确认运行 DSH 的用户目录；仅当 DSH 使用默认目录时，才用 `$HOME\.dsh`。已有 `DSH_HOME` 环境变量时沿用其值：

   ```powershell
   $dshHome = if ($env:DSH_HOME) { $env:DSH_HOME } else { Join-Path $HOME '.dsh' }
   $desktopProfile = Join-Path $dshHome 'profiles\desktop'
   $packageFile = Join-Path $desktopProfile 'package.json'
   $patchFile = Join-Path $desktopProfile 'cordis.patch.yml'

   "DSH_HOME: $dshHome"
   Test-Path -LiteralPath $packageFile -PathType Leaf
   Test-Path -LiteralPath $patchFile -PathType Leaf
   ```

   两项都应输出 `True`。若有 `False`，先核对当前登录用户、运行实例和实际 `DSH_HOME`，不要继续安装。文件存在后再检查包配置：

   ```powershell
   $profilePackage = Get-Content -LiteralPath $packageFile -Raw | ConvertFrom-Json
   $profilePackage.name
   $profilePackage.dsh.profile.bundles
   Get-Content -LiteralPath $patchFile
   ```

   `ConvertFrom-Json` 不应报错；`bundles` 列表中应有 `@deepseek-ai/dsh-base` 和 `@deepseek-ai/dsh-web-app`。`cordis.patch.yml` 只读查看，核对其中原有插件和引用的绝对路径；不要运行其中的文本。若实际 profile 有不同的 bundle 结构，应先按该实例的配置确认，不能直接套用上述判定。

3. 对 `package.json` 中每个 `link:` 本地依赖检查路径；普通版本号和其他协议的依赖不在此检查范围：

   ```powershell
   $profilePackage.dependencies.PSObject.Properties |
     Where-Object { $_.Value -is [string] -and $_.Value.StartsWith('link:') } |
     ForEach-Object {
       $target = $_.Value.Substring(5).Replace('/', '\')
       [pscustomobject]@{ Dependency = $_.Name; Path = $target; Exists = Test-Path -LiteralPath $target }
     } | Format-Table -AutoSize
   ```

   `Exists` 应为 `True`。若为 `False`，先核对 `link:` 路径及该实例原有依赖，再安装本插件，避免混淆故障来源。`cordis.patch.yml` 里出现的绝对路径也应分别用 `Test-Path -LiteralPath '<实际路径>'` 检查。
4. 备份上述两个 profile 文件和计划修改的自定义 preset 文件。安装只应追加本插件内容，不覆盖已有插件配置。
5. 核实要暴露的每条 API 的用途、HTTP 方法、参数、响应、权限和数据级别。写接口（POST、PUT、PATCH、DELETE）须确认目标 DSH 的审批策略。首轮建议只用只读 GET 接口验收。

## 3. 构建插件

在独立插件目录执行：

```powershell
Set-Location '<dsh-api-tools 仓库的绝对路径>'
git rev-parse --show-toplevel # 应为当前插件目录
npm ci
npm run typecheck
npm run build
Test-Path .\lib\index.js
Test-Path .\lib\tool.js
Test-Path .\lib\client.js
Test-Path .\lib\typert.host.js
Test-Path .\lib\typert.remote-client.js
```

五个 `Test-Path` 都必须为 `True`。若系统默认 Node 不满足要求，先切换到符合 `package.json` 的 Node 再构建。`lib/` 被插件 Git 忽略，**本地 `file:` 安装前必须先构建**；将来若从 Git URL 或发布包安装，应在交付包内包含构建产物并验证 `files` 清单，不能假定 Git 仓库会携带 `lib/`。

## 4. 安装到桌面版 profile

使用桌面版左侧“插件”页的“添加插件”，填入本插件仓库的绝对路径。预览应显示包名 `dsh-api-tools`、版本和组合包声明。确认后安装并启用。

检查 `$DSH_HOME/profiles/desktop/package.json`：`dependencies` 中有 `dsh-api-tools`，`dsh.profile.bundles` 中也有 `dsh-api-tools`。桌面版“已安装”列表应出现该包；打开组合包详情，应看到 API 配置区。该组合包只加载配置界面；此时 Agent 工具还不应出现。**不要**把 `dsh-api-tools/tool` 作为宿主顶层行插入；它只能嵌在所选 Agent preset 的 `plugins` 列表中。

本插件界面可以保存草稿、导出 `dsh-api-tools.config.json`，也可以创建独立 Agent preset。草稿在当前桌面应用的 localStorage；导出本身不装载工具。界面中的 Token 字段只填**环境变量名**，不能填密钥值。

## 5. 创建独立 Agent preset

在插件详情的“创建独立 Agent preset”区域输入新名称，例如 `hello-test`，点击“创建新 Agent preset（重启后生效）”。宿主会向 `$DSH_HOME/profiles/desktop/cordis.patch.yml` 追加一个 `@deepseek-ai/dsh-agent-preset` 插入行，并在同目录留下修改前的 `.bak` 备份。名称须以小写字母开头，只包含小写字母、数字和连字符，最多 40 字符。若该 preset 声明已存在会拒绝创建，**不会覆盖或修改已有 preset**。新 preset 只含本批 API 工具；它不是对 `standard` 或其他 Agent 的追加。

操作完成后**完全退出并重启 DSH 桌面版**，在新会话的模式选择器中选择 `API 测试 hello-test`，或到设置中的“Agent 预设”核对卡片。既有会话不自动切换。应用按钮调用的是桌面版宿主远程服务，不能把导出 JSON 误认为已经应用。创建后的配置若需更改，请用新名称再创建一个 preset；旧 preset 的清理由用户在确认没有会话依赖后单独处理。当前 DSH 已不读取 `$DSH_HOME/.agent-presets/<id>/` 旧式目录；此前版本创建的同名目录不代表 preset 已注册，也不会阻止本版按同名写入 profile 声明。

界面仍保留手工导出 JSON 的方式。以下是追加到 `desktop/cordis.patch.yml` 的声明结构，供审核与排查：

```yaml
- insert:
    - id: preset-dsh-api-hello-test
      name: '@deepseek-ai/dsh-agent-preset'
      config:
        id: dsh-api-hello-test
        name: API 测试 hello-test
        description: 独立 API 工具 Agent preset
        order: 100
        plugins:
          - id: tool-api-collection
            name: dsh-api-tools/tool
            config:
              baseUrl: https://api.example.com
              tokenEnv: DSH_API_ORDER_TOKEN
              timeoutMs: 15000
              maxResponseChars: 20000
              endpoints:
                - name: get_order
                  description: 根据订单号查询订单，仅返回已授权字段
                  method: GET
                  path: /orders
```

将示例值替换为已审核的真实 API。`baseUrl` 只能是 HTTP(S) 的协议、域名及可选端口，不含路径、凭据、查询或片段；`path` 以单个 `/` 开头，不含查询或片段。工具名以字母开头，后续仅字母、数字、下划线或连字符，最多 64 字符，并须在该 Agent 可见的其他工具中唯一。`description` 应告诉 Agent 何时调用、参数含义和结果含义，不写密钥或敏感样例。接口路径与方法由管理员固定，Agent 只能提供 `query`、`body` 两个 JSON 字符串参数；`GET` 不接受 body。

`tokenEnv` 可省略；若填写，必须以 `DSH_API_` 开头且只含大写字母、数字、下划线。将真实 Token 只注入 DSH 宿主进程的同名环境变量，不能放进 YAML、JSON、桌面应用草稿、Git 或日志。当前插件只支持 Bearer Token；其他鉴权方式需要先开发适配。对多个不同服务地址应分不同插件实例或扩展配置模型，不能让 Agent 自由选择 URL。

桌面应用导出的 JSON 与上面的 `config` 内容对应，供审核或另行集成。当前没有“上传 JSON 后自动启用”的接口。手工编辑 preset 后按目标 DSH 的 reload 机制或重启实例，并用新会话选择该自定义 preset。

## 6. 验收标准

1. 桌面版“已安装”列表有 `dsh-api-tools`，组合包已启用，详情中出现 API 配置区；页面无插件加载错误。
2. 原有普通 Agent preset 不出现本批 API 工具；自定义 preset 的新会话只出现其配置的 API 工具。
3. 用一条已授权的只读 API 调用验收：核对请求路径、查询参数、HTTP 状态、`body` 和 `truncated`。4xx/5xx 会作为工具错误返回，错误消息最多携带 500 个响应字符；目标 API 的错误正文也不得包含密钥或其他敏感信息。
4. 用无效参数、未设置 Token、超时和超出响应上限的场景核对错误或截断行为；检查服务器日志和会话记录没有密钥值。
5. 对写接口单独核对 DSH 的审批提示、拒绝路径及目标服务审计记录。未通过审批验收前不要给 Agent 暴露写接口。

这些是目标桌面版验收步骤，**不是已通过的桌面应用运行结果**。旧版曾成功创建 `.agent-presets` 目录，但当前 DSH 不读取该目录；尚未验证新版 profile 声明在真实桌面版列表中出现或由 Agent 调用。

## 7. 回退

若新建 preset 的工具调用异常，先在新会话切回原有 preset。确认没有会话依赖后，在 `$DSH_HOME/profiles/desktop/cordis.patch.yml` 中只移除该 preset 对应的 `# dsh-api-tools preset: <id>` 和紧随其后的 `- insert` 块，再重启 DSH；修改前先备份，不能回滚期间其他人新增的配置。若配置界面也需移除，在桌面版“插件”页停用并卸载 `dsh-api-tools`。旧版创建的 `.agent-presets` 目录未被当前 DSH 加载，清理前仍须逐项核对，插件不会自动删除。插件源码仓库、上级 workspace 和其他插件 Git 仓库不因回退而删除。
